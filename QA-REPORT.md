# OshiCart Full Platform QA Report

**Audit date:** 2026-08-15  
**Target:** Production (`https://oshicart.com`) plus local source review  
**Source:** `master` at `510dd3e`  
**Viewports:** Desktop Chromium and 375 px mobile; Lighthouse mobile emulation  
**Safety scope:** Production writes were explicitly approved for one `QA (delete me)` merchant and exactly three QA-labelled orders against OshiCart Demo Store. No real merchant/store setting was changed, no fourth order was created, and no privileged/service-role probe was used.

## 1. Executive summary

**Overall health: Red / not release-ready.** The public site, production build, core order arithmetic, rental capacity warning, invoice totals, normal login/logout, tenant isolation and money-column protection are generally healthy. One P0 money defect remains: every Settings save forces `vat_inclusive=false`, which can turn an existing VAT-inclusive catalogue into VAT-exclusive pricing and add 15% at checkout. P1 failures also block the merchant Orders page, break password recovery, omit rental dates from buyer/merchant records, bypass email ownership verification, and leak goods fulfilment language into service/accommodation flows.

The approved live-write scope is complete: one throwaway merchant, four QA products, one coupon, one block-out and exactly three demo-store orders were created. Product, online-service and day-rental submissions/invoices were exercised. A fourth night-rental order was deliberately not submitted. Dashboard order transitions, refund/credit-note generation and rental returns remain untestable because the production Orders page redirects the configured QA merchant to Setup (QA-024), not because approval is missing.

### Test result snapshot

- `npm run build`: **PASS** (Next.js 16.1.6, 106 routes). Non-fatal warnings: deprecated middleware convention and Edge Runtime static-generation limitation.
- All 13 `scripts/check-*.ts` checks: **ALL PASS** (`billing-period`, `branding-gate`, `coupon-templates`, `dashboard-nav`, `payment-methods`, `payment-reminders`, `plan-features`, `public-tier-reads`, `pwa-helpers`, `rentals`, `select-star`, `service-mode`, `statements`).
- Existing safe production Playwright subset: **10 passed, 2 auth tests skipped, 1 stale marketing assertion failed**. The failure expects copy no longer present; the page itself renders.
- Lighthouse mobile: home **70/94/100/100**, storefront **72/86/100/100**, product **80/95/100/100** for Performance/Accessibility/Best Practices/SEO.
- Findings: **1 P0, 8 P1, 11 P2, 5 P3** (25 total).

1. **QA-020 (P0) — Saving Settings silently forces VAT-inclusive stores to VAT-exclusive pricing.**
2. **QA-024 (P1) — The Orders page redirects a fully configured merchant to Setup.**

## 3. Ranked UI/UX improvements

1. **Protect pricing semantics before any UI polish.** Evidence: Settings forces `vat_inclusive=false` on every save. Make inclusive/exclusive VAT an explicit, preserved choice; show a before-save warning when the choice changes; add checkout/invoice snapshots for both modes.
2. **Restore the merchant's operational home.** Evidence: a configured merchant cannot open Orders because a denied merchant-column query is misread as “no merchant.” Use the owner RPC consistently, show a true error state instead of redirecting, and test every dashboard route as a newly configured merchant.
3. **Make identity recovery trustworthy.** Evidence: signup silently confirms email ownership and password recovery returns 500 twice. Require confirmation, repair recovery delivery, and show a resumable setup checklist with clear recovery/support states.
4. **Build one fulfilment-language model for goods, appointments, online work, on-site services, day hire, and accommodation.** Evidence: COD/pickup language survives into submitted online-service WhatsApp/invoices and rental records lose the hire period. Define nouns/actions/date fields once and reuse them in product detail, checkout, WhatsApp, tracking and invoices.
5. **Make discovery location-aware.** Evidence: region selection works but no town cascade exists. After choosing a region, display a searchable town selector, preserve selections in the URL, show active filter chips, and add a “No stores in this town—browse the region” fallback.
6. **Improve mobile control ergonomics and accessibility together.** Evidence: Account Settings overflows to 415 px, the sort select is unlabeled and core CTAs fail contrast. Make grid children shrink, wrap long identities, use 44 px targets, visible labels, AA-safe theme tokens and clear focus rings.
7. **Unify trust signals.** Evidence: two call numbers and two referral trial lengths appear in one journey. Store support contacts, trial duration, plan pricing and commission values in shared configuration consumed by web pages, messages and PDF generators.
8. **Make social previews product-specific.** Evidence: a no-photo product shares the store card, while photo products can expose raw aspect ratios. Compose a branded 1200×630 preview containing store name, product name, price/unit and a contained product image; add screenshot tests for home/store/product OG routes.
9. **Give referral agents a real post-application journey.** Evidence: successful application is a dead end and there is no agent dashboard. Show application status, referral link copying, demo-store access, referred merchant milestones, commission ledger, handbook and support from a least-privilege dashboard.
10. **Treat documentation as a generated product surface.** Evidence: stale web TOC, missing section parity, clipped PDF content and awkward handbook page breaks. Keep guide content in structured data, generate web/PDF numbering from it, and render every PDF page in CI for visual review.
